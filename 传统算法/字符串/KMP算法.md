# KMP算法

> [!question] 问题
> 给定一个模式窜 P 和 一个主串 S，求模式串 P 在 主串 S 中出现的位置。
> - 字符串的下标从 1 开始
> 

暴力做法是很简单的，只需要遍历主串的每一个下标，然后逐个字符判断模式串是否匹配，时间复杂度为 $O(len(P)\cdot len(S))$ ；

那么很显然，暴力做法的时间消耗很大，而 $KMP$ 算法的时间复杂度是优秀的；

## 前后缀

> 首先介绍什么是前后缀

对于一个字符串：
- **前缀（Prefix）**：从字符串开头开始的连续子串。
- **后缀（Suffix）**：从字符串末尾结束的连续子串。

例如：

```txt
s = "abcdef"
```

- 前缀：
```txt
a
ab
abc
abcd
abcde
abcdef
```

- 后缀
```txt
f
ef
def
cdef
bcdef
abcdef
```

## 相等前后缀


> [!NOTE] **相等前后缀** 
> 一个字符串中，某个**前缀**和某个**后缀**完全相等。

>在 KMP 中讨论相等前后缀时，默认**不包括字符串本身**，因为整个字符串既是前缀也是后缀，如果算进去就没有区分意义。

例如：

```txt
s = "ababa"
```

- 前缀（不包含自身）：

```txt
a
ab
aba
abab
```

- 后缀（不包含自身）：

```txt
a
ba
aba
baba
```

所以它的相等前后缀有：

```txt
a
aba
```

其中最长的相等前后缀是：

```txt
aba
```


## next 数组

> [!NOTE] **next 数组**
> $next[i]$ 表示**模式串** $P[1 \sim i]$ 中，**最长相等前后缀的长度**。

也就是说，$next[i]$ 只和**模式串**有关，和主串无关。

例如：
```txt
P = "ababa"
```

| $i$ | $P[1 \sim i]$ | 最长相等前后缀 | $next[i]$ |
| --- | --- | --- | --- |
| 1 | `a` | 无 | 0 |
| 2 | `ab` | 无 | 0 |
| 3 | `aba` | `a` | 1 |
| 4 | `abab` | `ab` | 2 |
| 5 | `ababa` | `aba` | 3 |

所以：
```txt
next = [0, 0, 1, 2, 3]
```


> [!important] 作用
> 当模式串匹配到第 $j$ 位后失配时，不需要从头重新匹配，而是让 $j$ 跳到 $next[j]$。


## 求next 数组

```cpp
ne[1] = 0;
for(int i = 2, j = 0 ;i <= n;i++){
	while(j && P[i]!=P[i+1]) j = ne[j];
	if(P[i] == P[j+1])j++;
	ne[i] = j;
}
```

双指针： $i$ 扫描模式串，$j$ 扫描前缀。
- $i$：当前要求 $next[i]$ 的位置。
- $j$：当前已经匹配上的前缀长度。

初始化：$ne[i] = 0$ ，$i=2$，$j=0$；
每轮 $for$ 循环，$i$ 向右走一步
1. 若 $P[i]\; !=P[j+1]$ ，让 $j$ 会跳到能匹配的位置，
	如果找不到能匹配的位置，$j$ 回跳到 $0$
2. 若 $P[i] == P[j+1]$ ，让 $j+1$ ，<font color="#ff0000">指向匹配前缀的末尾</font>
3. $next[i]$ 等于 $j$ 的值

![[next数组.png]]



> [!NOTE] 分析时间复杂度
> `j` 指针的总移动步数决定了算法的总执行次数。
> - 在每轮 `for` 循环中，`i` 向右移动一次，共移动 `n` 次；
> - **指针 `j` 每次成功匹配时向右移动，最多增加 `n` 次；**
> - 当发生失配时，`j` 会根据 `next` 数组向左跳转，但整个过程中向左跳转的总次数不会超过向右移动的总次数，因此也不会超过 `n` 次。
>
因此，`j` 的总移动次数不超过 `2n`，整个求 `next` 数组的过程时间复杂度为：$O(n)$


## 模式串与主串匹配

有了 $next$ 数组以后，就是真正的匹配了；
和求 $next$ 数组的代码相似；

双指针：$i$ 扫描主串， $j$ 扫描模式串

初始化：$i=1$ ，$j=0$ 
每轮 $for$ 循环，$i$ 向右走一步
1. 若 $P[i]\; !=P[j+1]$ ，让 $j$ 会跳到能匹配的位置，
	如果找不到能匹配的位置，$j$ 回跳到 $0$
2. 若 $P[i] == P[j+1]$ ，让 $j+1$ 
3. 若匹配成功，输出匹配位置。

```cpp
for(int i=1,j=0;i<=n;i++){
	while(j && S[i]!=P[j+1])j = next[j];
	if(S[i] == P[j+1])j++;
	if(j == n)cout<<i-n+1<<'\n';
}
```




```cpp
#include <bits/stdc++.h>
using namespace std;
// #define ll long long
const int N = 1e6 + 5;
int next[N];
string P,S;
// S为主串，P为模式串
void create(){
    // O(n) n为模式串长度
    for(int i = 2,j = 0; i < P.size(); i++){
        while(j && P[i]!=P[j+1]) j = next[j];
        if(P[i] == P[j+1])j++;
        next[i] = j ;
    }
}
int main(){
   	cin>>S>>P;
    S='-'+S;P = '-'+P;
    create();
    // O(m) m为主串长度
    for(int i = 1,j = 0;i<S.size();i++){
        while(j && S[i]!=P[j+1])j = next[j];
        if(S[i] == P[j+1])j++;
        if(j == P.size()-1){
	        printf("%d",i-P.size()+2);
	        j = ne[j];
        }
    }
    
    // 可以输出next数组
    for(int i=1;i<P.size();i++){
        cout<<next[i]<<" ";
    }
    return 0;
}
```

# 注意
### KMP：完整匹配后的回退

完整匹配后，建议立即执行：

```cpp
if (j == len) {
    ans++;       // 找到一次匹配
    j = ne[j];   // 保留可复用的最长相等真前后缀
}
```

其中 `len` 是模式串长度。

#### 为什么有些字符模板不写？

如果使用以 `'\0'` 结尾的字符数组，完整匹配后 `j == len`，下一轮会比较：

```cpp
S[i] != P[len + 1]
```

此时 `P[len + 1]` 是结束符 `'\0'`，与主串中的正常字符不同，所以会自动进入：

```cpp
while (j && S[i] != P[j + 1]) j = ne[j];
```

因此，这类模板是**把回退推迟到下一轮**，并非不需要回退。它依赖末尾存在一个不会与正常元素相等的结束符。

#### 为什么整数数组不能直接照搬？

整数数组末尾填充的 `0` 可能也是合法数据，无法保证下一轮失配。

例如：

```cpp
主串：[0, 0]
模式：[0]
```

正确匹配次数为 `2`。如果模式数组有效范围外也是 `0`：

1. 第一次匹配后，`j = 1`，计数一次。
2. 下一轮与模式数组末尾填充的 `0` 比较，仍然相等。
3. `j` 增加到 `2`，导致漏掉第二次匹配。

#### 为什么回退到 `ne[j]`，而不是 `0`？

为了保留已经匹配的后缀，继续寻找**重叠匹配**。

例如：

```cpp
主串：aaaa
模式：aaa
```

有两次匹配，起点分别为 `1` 和 `2`。

第一次匹配后，令 `j = ne[3] = 2`，保留末尾的 `aa`，再匹配一个 `a` 就能找到第二次。如果直接令 `j = 0`，就会漏掉重叠匹配。

**推荐统一写法：完整匹配后立即执行 `j = ne[j]`，不依赖结束符，适用于字符和整数序列。**
